# Мой путь: питание, статистика и перенос истории

Обновление существующего мобильного приложения для личного учёта тренировок и питания. Финансы отложены по просьбе пользователя.

## Требования
- Четыре приёма: завтрак, обед, перекус, ужин. Любое количество продуктов; количество в граммах; редактирование и удаление записей.
- Поиск обычных продуктов и магазинных товаров. Не обещать полного покрытия всех продуктов интернета. Для каждого источника сохранять идентификатор, дату и состав на 100 г; в истории хранить снимок состава.
- КБЖУ, клетчатка, витамины, минералы и омега-3. Итоги по приёму и дню, процент личной цели. Неизвестный нутриент не равен нулю; частичные итоги явно помечены.
- Редактируемые личные цели загружаются отдельным приватным JSON или задаются на устройстве. Публичный исходный код не содержит персональных значений. Единицы явно указаны; пустая цель не даёт процента. История изменений целей сохраняется. Примечание из файла целей показывается в форме.
- Вес тела вводится независимо от тренировок. Общий выбор дат для графиков веса, любого нутриента, средних и процентов выполнения. Пропуски не считаются нулевыми днями; количество учтённых дней видно.
- Для каждого упражнения график максимального веса выполненного подхода за тренировку и процент изменения между первой и последней записью периода. Показывать повторы; не называть рост нагрузки приростом силы. Нулевая начальная нагрузка не даёт процента. В калистенике показывать секунды/повторы/попытки отдельно от кг.
- Старые записи продолжают читаться из прежнего ключа. Поддержать JSON v1 и CSV из прежнего приложения, полную копию v2. Предпросмотр импорта, идемпотентное объединение, по умолчанию сохранить существующие значения при конфликте. CSV содержит только выполненные подходы; исходные даты завершения и черновики не восстанавливаются выдуманными данными.
- Личные резервные копии и дневники никогда не включать в публичный репозиторий.

## Подход
Расширить существующий статический HTML/CSS/JS и офлайн-кеш: не нужен новый аккаунт или перенос адреса. Данные тренировок остаются в прежнем хранилище, питание/вес/цели — в отдельном версионированном. Чистые функции математики/импорта отделены от интерфейса. SVG-графики сопровождаются таблицами.

Варианты справочника: только ручной ввод не соответствует запросу; только Open Food Facts не покрывает полноту микроэлементов; серверный агрегатор добавляет хостинг и ключи. Выбран комбинированный статический справочник USDA SR Legacy (официальная выгрузка, CC0), поиск Open Food Facts по явной кнопке и личные продукты. Для распространённых продуктов добавить русские названия и поисковые соответствия; оригинальное описание и источник остаются доступны. Не смешивать недостающие нутриенты брендового товара со средними данными другого продукта.

## Проверка и доставка
Модульные проверки пересчёта, единиц, неполноты, импорта и диапазонов; проверка реального пользовательского CSV вне репозитория; мобильная проверка основных действий, перезагрузки, импорта и офлайн-режима. Готовые изменения публикуются в отдельной ветке и PR, основной работающий экземпляр обновляется после решения пользователя о применении.
